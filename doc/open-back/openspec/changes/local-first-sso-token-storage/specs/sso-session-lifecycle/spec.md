## Purpose

统一登录凭证的业务期限、Cookie 保存期限、有效期内续期、退出反馈及访客行为，使不同来源的凭证在应用站使用时保持相同的身份规则。该能力依赖已有后端统一鉴权和注销保证，约束前端不得通过缓存、迟到响应或错误回退恢复已失效身份。

本能力的新凭证生命周期在凭证版本 2 激活后适用；版本 1 的兼容准备行为受 `sso-release-validation` 中的版本切换要求约束。

## ADDED Requirements

### Requirement: 记住我与 Cookie 保存策略

系统 SHALL 保持登录界面默认不勾选记住我，并将用户选择正确传递给既有后端。勾选后的业务天数 SHALL 以后端统一配置为准，未配置时默认为 14 天；持久 Cookie 的保存截止 SHALL 为实际业务截止后 1 天。未勾选时 SHALL 使用不含 Max-Age 与 Expires 的会话 Cookie，其业务有效期仍由后端决定。

#### Scenario: 勾选记住我且未配置业务天数
- **WHEN** 用户勾选记住我并完成登录，后端未配置其他业务天数
- **THEN** 业务有效期为 14 天，持久 Cookie 按该业务截止后再保留 1 天设置保存期限

#### Scenario: 后端使用不同的业务天数
- **WHEN** 后端配置了有效业务天数并返回实际截止时间
- **THEN** 前端使用后端实际截止时间决定 Cookie 保存期限，不再套用另一套前端默认天数

#### Scenario: 用户未勾选记住我
- **WHEN** 用户保留默认未勾选状态并完成登录
- **THEN** 浏览器 Cookie 不包含 Max-Age 与 Expires，且该会话仍受后端业务截止时间限制

#### Scenario: Cookie 值正确但保存属性不符
- **WHEN** 凭证写入后 token 值符合预期，但浏览器中的保存属性不符合该 token 的有效记住我策略
- **THEN** 验收仍判定写入行为不符合要求，不能仅凭 token 值正确判定属性设置成功

### Requirement: 业务截止独立于额外保留时间

系统 MUST 在达到业务截止时间时停止使用和续期该登录凭证，并要求重新登录。额外 1 天 SHALL 仅表示 Cookie 的物理保留缓冲，不增加业务使用权、续期权或离线宽限；仅执行读取 MUST 不延长任何后端业务期限或 Cookie 保存截止。

#### Scenario: 业务截止之前
- **WHEN** 当前时刻仍早于业务截止且满足后端规定的续期条件
- **THEN** 系统可以申请后端续期，但不自行改变凭证中的截止时间

#### Scenario: 精确达到业务截止
- **WHEN** 当前时刻达到或超过业务截止，即使只达到边界时刻
- **THEN** 该凭证不得用于业务请求或续期，系统要求重新登录

#### Scenario: Cookie 仍处于额外保留日
- **WHEN** Cookie 仍可读取但业务截止已经过去，且尚未到达业务截止后的第 1 天
- **THEN** 系统仍将凭证视为业务失效，不将 Cookie 存在解释为继续登录有效

#### Scenario: 重复读取有效 token
- **WHEN** 应用仅重复读取或展示已有凭证而未获得后端成功续期结果
- **THEN** 业务截止及 Cookie 保存截止保持不变

### Requirement: 可信的会话元数据

系统 SHALL 仅凭后端签名 token 独立重建会话身份、签发时间、业务截止、续期时机和有效记住我策略；这些必要元数据 MUST 不仅存在于一次登录或续期响应，也不得依赖未签名 Cookie 附加字段。响应中的元数据 SHALL 与 token 中的映射一致。前端解析 SHALL 仅用于生命周期调度，MUST 不替代后端验签与鉴权；损坏、缺少必要字段或时间值不合法的凭证 MUST 明确失败，不猜测有效期。

#### Scenario: 必要元数据缺失
- **WHEN** 签名 token 无法独立提供当前功能所需的任一会话元数据，即使登录响应中存在该字段
- **THEN** 前端报告契约或凭证错误，不自行补造 14 天期限或新的会话身份

#### Scenario: 页面刷新后只有持久 token
- **WHEN** 页面刷新后登录响应和运行时状态已丢失，仅能读取已保存的 token
- **THEN** 系统仍能重建全部必要会话元数据，并保持原业务截止、续期条件和记住我策略

#### Scenario: 响应元数据与 token 不一致
- **WHEN** 登录或续期响应中的元数据与其签名 token 所承载的信息不一致
- **THEN** 系统明确报告契约错误，不选择较晚截止或更宽松保存策略继续使用

#### Scenario: 非法时间或损坏凭证
- **WHEN** 凭证无法解析，或截止时间不是合法、安全的时间值
- **THEN** 系统不将该凭证作为可用登录态，也不回退另一份旧身份掩盖问题

#### Scenario: 后端拒绝客户端认为有效的凭证
- **WHEN** 前端预判断认为凭证尚有效，但既有后端返回明确鉴权失效
- **THEN** 系统以后端结果为准，处理对应会话失效，不以本地解析结果继续授权

### Requirement: 仅在有效期内申请既有后端续期

系统 SHALL 在后端规定的续期时机已到达且业务期限尚未结束时，为实际业务凭证获取申请既有后端续期。没有用户业务活动时 MUST 不通过定时任务自行延长身份；后端续期失败 MUST 不伪装为注销成功、登录成功或新的存储凭证。

#### Scenario: 尚未到续期时机
- **WHEN** 凭证有效但尚未达到后端规定的续期时机
- **THEN** 系统使用当前凭证，不额外发起续期

#### Scenario: 有效期内业务请求触发续期
- **WHEN** 业务请求获取凭证时已满足后端续期条件且未达到业务截止
- **THEN** 系统先完成所需续期及原来源更新，再使用更新后的凭证发送业务请求

#### Scenario: 续期网络失败
- **WHEN** 续期发生网络错误或后端服务错误
- **THEN** 本次依赖续期的操作明确失败并允许重试，不把故障解释为确认注销，也不向备用存储写入 token

#### Scenario: 后端未给出有效的新截止
- **WHEN** 续期响应不属于预期会话，或没有可接受的新业务截止
- **THEN** 系统不伪造更晚期限，不以该响应延长 Cookie 生命周期

### Requirement: 续期更新必须保持认证来源

系统 MUST 将每次解析得到的凭证来源保持到该次续期完成，并只更新该原来源的相同存储范围。来源为 A 的 RPC 凭证 MUST 只在 A 更新，写入失败时 MUST 不在 B 保存替代副本；本地既有来源 SHALL 只更新其原有范围。共享父域 Cookie 的更新 SHALL 保持原 Domain、Path 和名称。

#### Scenario: RPC 来源成功续期
- **WHEN** B 使用来自 A 的 token 获得后端续期结果
- **THEN** 新 token 只更新到 A 的原来源，B 的任何持久存储均不产生该 token 副本

#### Scenario: A 无法保存续期结果
- **WHEN** A 来源的续期响应有效但原来源更新被拒绝或超时
- **THEN** 操作报告失败，不改为写 B，也不将未保存的结果保留为后续调用缓存

#### Scenario: 本地既有凭证续期
- **WHEN** 凭证来自 B 已存在的本地存储或 B 可见的共享父域 Cookie
- **THEN** 系统只更新同一来源范围，不改写其他模式或建立新的 host-only Cookie 副本

### Requirement: 迟到身份操作不得恢复旧会话

系统 MUST 防止退出、重新登录或身份切换之前发起的读取、访客生成及续期结果覆盖之后的身份状态。同页并发续期 SHALL 合并；原来源会话已经改变时更新或删除 MUST 失败而非覆盖新会话，自动重新读取 SHALL 有界。该行为 MUST 不被宣传为浏览器多标签页的原子事务保证。

#### Scenario: 续期未返回时用户退出
- **WHEN** 用户退出后才收到此前发起的续期结果
- **THEN** 系统丢弃旧结果，不恢复 token、用户缓存或旧身份连接

#### Scenario: 慢操作遇到新登录
- **WHEN** 新用户已完成登录后，旧读取、访客生成、续期或删除操作才完成
- **THEN** 旧操作不得覆盖或删除新用户的登录凭证

#### Scenario: 多个同页请求需要续期
- **WHEN** 同一会话的多个调用同时到达续期条件
- **THEN** 系统共享该次未完成续期，不无条件并发覆盖原凭证

#### Scenario: 原来源在条件更新前已变化
- **WHEN** 原来源已不再保存本次操作预期的会话凭证
- **THEN** 系统报告会话变化，最多重新读取一次，不无限重试或恢复原身份

### Requirement: 退出与失效消费既有后端统一保证

系统 SHALL 沿用已确认的后端统一鉴权、注销与会话失效能力，不新增后端注销机制。前端观察到对应会话已注销或明确鉴权失效后 MUST 清理该会话的可见凭证及派生用户状态，停止旧身份操作并引导重新登录。显式凭证清理 SHALL 先取消本页当前身份操作、清理所选模式下 B 可见凭证，再尝试清理 A 的同一会话；清理 MUST 不删除后来建立的新会话。

#### Scenario: A 退出后 B 仍持有旧值
- **WHEN** A 完成既有统一注销，而 B 带旧凭证访问 HTTP、上传或 WebSocket 服务
- **THEN** 联调验证后端按既有能力拒绝旧会话，B 消费该结果并清除旧身份状态，不继续重用旧凭证

#### Scenario: 共享凭证已经被其他页面删除
- **WHEN** 当前会话清理时发现共享来源已为空
- **THEN** 凭证清理幂等完成，不将空值当作必须恢复的登录状态

#### Scenario: 清理过程中出现新的登录
- **WHEN** 旧会话清理尚未完成，而来源已经保存新会话
- **THEN** 清理不删除新会话，旧操作不能阻止新身份继续工作

### Requirement: 用户资料缓存不作为登录依据

系统 SHALL 将用户资料缓存仅用于展示，不视为鉴权或会话仍有效的证明。发现当前会话缺失、到期或明确失效时 MUST 清理对应缓存；页面恢复展示或重新可见时 SHALL 重新读取并同步状态。暂时性读取失败 MUST 不被记录为已确认的全局注销事件。

#### Scenario: 无 token 但存在旧用户资料
- **WHEN** 当前会话已确认不存在，而当前页仍保存旧用户资料
- **THEN** 页面清除旧身份展示，其他用户资料消费者不再将旧缓存视为有效登录

#### Scenario: 从后台或浏览器历史恢复页面
- **WHEN** 页面重新可见或由浏览器恢复，而认证站会话可能已经变化
- **THEN** 页面重新读取当前状态并更新展示，不永久停留在初次挂载时的用户身份

#### Scenario: 用户资料缓存写入不可用
- **WHEN** token 本身可正常读取及用于后端鉴权，但展示缓存无法保存
- **THEN** 缓存失败不改变 token 的认证来源或后端有效性，且不得制造另一份持久 token 副本

### Requirement: 访客身份与真实登录隔离

系统 SHALL 仅在允许匿名业务且调用方提供访客生成能力时使用访客身份，并先完成真实本地登录凭证及 A 的查询。访客凭证 MUST 与真实登录凭证隔离，不遮蔽新登录、不覆盖 A 的登录 key；仅新生成访客可以按既有匿名功能保存在 B，RPC 返回值不享有该例外。

#### Scenario: B 有访客而 A 后来完成真实登录
- **WHEN** B 已保存访客凭证，而 A 已有真实登录凭证
- **THEN** 真实登录查询不被访客本地命中跳过，应用使用 A 的真实身份

#### Scenario: 允许匿名业务且真实凭证明确缺失
- **WHEN** 本地和 A 均成功确认没有真实登录凭证，且调用方提供访客生成能力
- **THEN** 系统可以读取或生成隔离的访客凭证，并保留调用方显式选择的存储模式

#### Scenario: 未提供访客生成能力
- **WHEN** 真实凭证明确缺失且调用方没有提供访客生成能力
- **THEN** getToken 返回 null，不自动创建访客身份

#### Scenario: 代理读取错误或真实登录已到期
- **WHEN** 真实凭证查询发生错误，或已有登录凭证达到业务截止
- **THEN** 系统不通过自动生成访客掩盖读取故障或绕过重新登录要求

#### Scenario: 访客生成期间完成真实登录
- **WHEN** 访客生成尚未完成时用户完成真实登录或执行退出
- **THEN** 迟到访客结果不覆盖新登录、不恢复旧身份，也不写入 A 的真实登录 key

### Requirement: 请求与长连接统一遵守生命周期

HTTP、下载、上传及 WebSocket 握手 SHALL 使用统一的可用凭证获取规则，并在发送有副作用请求前完成所需续期。系统 MUST 不自动重放已经发送的 POST 或上传；后端拒绝或断开旧身份 WebSocket 后 MUST 不无限使用旧 token 重连。更新 Cookie MUST 不被视为既有连接已经重新鉴权。

#### Scenario: 有副作用请求遇到续期
- **WHEN** POST 或上传发送前发现凭证需要续期
- **THEN** 系统先完成续期，且不因后续错误自动重复发送已发送的业务请求

#### Scenario: 后端使既有 WebSocket 失效
- **WHEN** 既有后端拒绝或断开已失效会话的连接
- **THEN** 前端停止旧身份状态及重复重连，并按当前会话结果重新登录或恢复允许的状态

#### Scenario: Cookie 更新但连接尚未重建
- **WHEN** 凭证成功续期并更新 Cookie，而旧 WebSocket 仍然存在
- **THEN** 系统不声称旧连接已经使用新 token 完成鉴权，连接有效性继续遵守既有后端协议
