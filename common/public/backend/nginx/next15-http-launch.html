结论先行

四个站点已统一到 Next.js 15.5.26，使用 HTTP / WS，由 Nginx 提供静态文件。上线分为“本机生成文件、上传到服务器、服务器执行脚本”三段。按下面顺序操作，无需手写 Nginx 配置或切换目录的命令。

四站构建和静态检查已通过，但真实登录、上传和聊天仍需在服务器验收。我们没有替你执行线上发布。此方案使用 Next.js 官方静态导出能力，线上不运行 Next.js 服务。

问题背景

common 是主站，Admin、IM、Passport 是另外三个站点。它们共用部分源码，但每站有自己的静态文件。构建脚本会自动执行子站的 npm run copy，随后构建四站，打成一个发布包。

发布脚本负责校验文件、保留旧资源、检查 Nginx、切换版本和回滚。API、数据库、邮件和 WebSocket 仍使用已有后端；脚本不会安装这些业务服务。详细原理可查阅前期技术评估，本次协议以本文的 HTTP / WS 为准。

详细步骤

1. 首次上线前，请运维确认一次

本机安装 Node.js 22 或更新版本。服务器为 Linux，已安装 Nginx、rsync、Python 3、Bash、GNU coreutils（常用系统命令）和 util-linux（提供 flock 命令）；你的服务器账号有 sudo 权限。

请运维确认 www、admin、im、passport 和 api 域名指向正确服务器，80 端口开放；后端 API 的 8888、WebSocket 的 8080 是实际端口，头像媒体域名可访问。端口不同或旧 Nginx 已配置相同域名时，由运维先调整。脚本不能替代这一步。

生产域名已写在四站的环境配置中。以后变更域名或协议，要重新构建，不能只改服务器上的环境变量。

2. 本机：生成发布文件

在编辑器中打开项目，终端进入仓库根目录 sparrow-js，执行：

node deploy/build-static.mjs && node deploy/package-static.mjs

脚本按锁文件安装依赖，复制共享代码，构建四站并检查产物；出错会停止。成功后，artifacts 文件夹中会出现三个要上传的文件：带发布编号的 .tar.gz 发布包、同编号的 .tar.gz.sha256 校验文件，以及固定名称的 server-release.sh 服务器脚本。

后文以 20260924-demo 为示例编号。操作时，把所有示例编号换成这次生成的实际编号。脚本名称始终是 server-release.sh，无需改名。每次上传本次打包生成的这三个文件；如服务器已有同名脚本，选择覆盖。不要上传源码或 node_modules。

3. 上传：把三个文件放到服务器

使用你已有的 SFTP 工具或服务器面板，通过自己的 SSH 账号登录服务器。创建 /tmp/sparrow-release 文件夹，将刚才的三个文件全部上传进去。无需在这里填写或分享服务器密码。

然后打开服务器面板的终端，或用已有 SSH 工具进入服务器终端，执行：

cd /tmp/sparrow-release

从这一步起，后面的命令都在服务器终端执行，保持当前文件夹不变。

4. 服务器：检查并准备新版本

核对示例编号已经替换，再执行：

sudo bash server-release.sh prepare 20260924-demo.tar.gz

脚本校验发布包、解压新版本，并保存新旧页面需要的静态资源。此时不会切换正在使用的网站。看到成功提示后再继续；如果校验失败、文件缺失或目录冲突，先按提示处理，不要跳过这一步。

5. 服务器：检查 Nginx 配置

每次发布都执行下面这一步，先备份并检查配置：

sudo bash server-release.sh configure 20260924-demo

脚本备份配置、安装本次配置，并执行 Nginx 检查，暂不重载服务。如果提示旧配置中存在相同域名，或 Nginx 未加载本次配置，把错误信息交给运维处理，再重新运行。看到“配置检查通过”后，再进入正式发布。

6. 服务器：正式切换版本

确认前面的步骤成功后，执行：

sudo bash server-release.sh publish 20260924-demo

脚本将四站一起切换到新版本，并加载需要的 Nginx 配置。输出中的 current 表示现在使用的版本，previous 表示可恢复的上一版。保留成功输出和发布包，便于后续排查。

任何错误都应先处理，不能仅凭命令执行完毕就认为上线成功。

7. 浏览器：确认网站真的可用

依次打开四个入口：主站、管理站、IM、Passport。管理站使用 admin 域名，旧 coder 域名会跳转过去。

切换中英文，进入内页后刷新。默认语言为主站 / 管理站中文、IM / Passport 英文；已保存的语言选择会继续使用。再用真实账号测试登录回跳、跨站登录状态和退出，测试头像 / 文件上传，以及 IM 消息发送接收和断线重连。

这些真实业务全部通过，才算上线完成。若页面能打开但登录或聊天失败，请检查已有后端和跨域配置；重新上传静态文件通常无法解决后端问题。

8. 出现问题：恢复上一版

在同一个服务器终端执行：

sudo bash server-release.sh rollback

脚本按记录恢复上一版。查看结果提示，再用浏览器检查四个入口和关键功能。首次上线没有上一版时无法用此方式回滚，需要运维恢复原有站点。不要手动删除旧版本或资源归档。

总结

本机构建 → 上传三个文件 → prepare → configure → publish → 浏览器验收。需要恢复时执行 rollback。整个流程由脚本处理文件和版本切换，你只需核对终端位置、发布编号及每一步的结果。
