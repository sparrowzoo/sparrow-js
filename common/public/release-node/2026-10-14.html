2026-10-14 发版说明

发布于 2026-10-14

摘要

本次更新完善代码生成器，可直接生成后台管理服务端、C 端后端 Server 及前端后台管理系统脚手架，减少项目初始化时的重复搭建工作。

同时修复部分国际化提示 Key，将全局 ErrorMessage 统一收敛到 default 配置中维护，并完善 AI Coding 文档 skill 的职责边界与代码规范，重构 BRD / PRD / TRD 文档规范，让业务依据、产品规则与技术方案各有明确的交付职责。

变更明细

新增功能

  • 后台管理服务端脚手架：完善代码生成器，支持直接生成后台管理系统的服务端工程骨架。
  • C 端后端 Server 脚手架：支持生成面向 C 端业务的后端服务工程骨架。
  • 前端后台管理系统脚手架：支持直接生成管理端前端工程，配合服务端脚手架完成项目基础搭建。

问题修复

  • 国际化提示 Key 修复：修复部分提示文案的 Key 引用问题，使相关提示使用对应的国际化文案。

重构优化

  • 全局错误提示统一维护：全局 ErrorMessage 统一使用 default 中的配置，减少重复配置与文案维护分散的问题。
  • 项目配置精简：移除 projectConfig.wrapWithParent 字段，同步清理新增与编辑表单、列表列、校验规则及中英文文案。
  • 文档 skill 职责边界完善：明确 req-writer、prd-writer 与 trd-writer 的输入、交付和交接职责；需求与产品评审聚焦业务目标、行为、范围和验收，纯技术机制交由 TRD 细化，涉及业务效果、范围或成本的变化须重新确认。
  • BRD 业务依据重构：补齐全景业务架构、当前项目与需求定位、核心痛点、业务解决方案，以及依赖的人员团队、业务服务和数据，为 PRD 提供可追溯的业务依据。
  • PRD / TRD 文档规范重构：PRD 承载完整产品规格、业务规则与验收场景；TRD 承接已确认的产品要求，细化架构、接口、数据、测试、部署与恢复方案。完整与轻量模式统一保留 TRD 章节结构，轻量模式按实际改动简写内容。
  • 文档内容与确认规范统一：业务文档围绕当前需求编写，skill 和模板维护过程单独留证；必要的人员、团队与职责信息须核实，不用占位词替代确认。文档末尾统一维护评审结论，分别记录审查状态、用户确认和下一环节授权，内容变化后同步更新。
  • AICoding 代码规范完善：完善可复用的 Java / Maven 整洁架构规范，明确模块职责、依赖方向与对象归属，并补充 MySQL 字段、主键、索引、审计及迁移约定。
