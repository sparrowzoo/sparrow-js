2026-10-12 发版说明

发布于 2026-10-12

摘要

本次发版围绕四条线展开：SEO 完善、登录态头像展示、头像上传体验升级与跨域 SSO 用户信息共享与解耦。其一，新增 JSON-LD 结构化数据与 openGraph 元信息，并统一站点各入口的标题与描述文案，帮助搜索引擎更准确地理解站点与产品。其二，登录后 header 用户菜单由占位图标改为展示用户真实头像，缺失自定义头像时回退系统占位图、加载失败兜底默认图标。其三，头像上传在能力下沉 sparrow-file、编辑页左右分栏的基础上，进一步修复上传后旧图缓存不刷新的问题，并优化预览触发时机。其四，把「读用户」收敛到 LoginUserProvider 单一 Context，父子组件通过 useLoginUser 共享同一份 LoginUser，HTTP（Fetcher/ChatApi）与 WebSocket（SparrowWebSocket）职责解耦，修改头像由后端重签 token 守护数据一致。

相关文章

本次登录态重构的设计与取舍，详见技术博客 《跨域 SSO 下的用户信息共享与解耦：Context、职责边界与 token 重签》。

变更明细

新增功能

  • SEO 结构化数据：新增 JsonLd 组件与五类 JSON-LD 生成器（Organization / WebSite / SoftwareApplication / Course / Person），首页注入 Organization + WebSite，产品页注入 SoftwareApplication，学习页注入 Course + Person，帮助搜索引擎理解站点结构。
  • 产品页元信息：file / im / passport / coder 产品页补齐 openGraph 标题、描述与类型。
  • 登录态头像展示：header 用户菜单由占位图标改为展示真实头像（getAvatar），无自定义头像回退系统占位图，加载失败兜底默认图标。
  • 登录用户共享：新增 LoginUserProvider 与 useLoginUser，把登录用户收敛为单一 Context 数据源，父子组件共享同一份 LoginUser，避免各处重复取 token、重复解码。
  • token 变更订阅：CrosStorage 新增 onTokenChange / notifyTokenChange，登录、登出、换头像等 token 变更统一广播，订阅组件自动刷新。

重构优化

  • 文件能力下沉：sparrow-file 服务新增通用裁剪参数 ImageCropperParam 与后处理策略 CropPostProcessStrategy，上传与剪切能力与业务解耦。
  • passport 业务化：上传接口拆分为通用文件上传 uploadImage 与修改用户头像 modifyUserAvatar 两步，文件存储与业务存储职责分离。
  • 头像编辑页重构：改为左右分栏布局，统一 passport 设计系统。
  • 预览时机优化：预览触发改用 onImageReady 回调，setState 改为函数式更新。
  • HTTP 与 WebSocket 职责解耦：Fetcher / ChatApi 专注请求-响应与 Authorization 头，SparrowWebSocket 专注实时通道、握手鉴权与鉴权失败清 token，MessageBroker 作为组装点接收 LoginUser 而非 token。
  • 头像重签保证一致：修改头像由后端重新签发包含新头像的 token，前端 setToken 覆盖并触发全局通知，父子组件与后续请求读到一致的用户信息。

问题修复

  • 头像缓存不刷新：上传成功后头像 URL 追加时间戳参数，强制浏览器加载新头像，避免显示旧图。
  • canvas 污染报错：跨域头像绘制后 canvas 被污染，预览 toDataURL 抛 SecurityError，已捕获并跳过，避免未捕获异常。
  • 头像预览跨域：客户端加载头像时设置 crossOrigin=anonymous，nginx 为头像资源添加 Access-Control-Allow-Origin 响应头，让初始跨域头像也能正常生成预览。
  • 清理调试断点：移除上传链路中遗留的 debugger 断点。
  • 加载失败兜底：头像无法渲染时自动回退默认头像，避免空白。

其他

  • 文案定位统一：网站、产品与学习入口的 title / description 统一为「跟着做过项目的人一起做项目」定位，强化 SEO 与品牌表达。
